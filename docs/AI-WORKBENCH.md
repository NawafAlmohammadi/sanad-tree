# AI implementation and source boundaries

The workbench has one conversation, hadith-to-tree extraction and adaptive graph practice. One configured external model is selected for the whole workbench. The live demo and portable package share application logic; their hosting adapters differ.

## Unified assistant

The server applies the scientific guide before retrieval: no invented scripture, judgements of persons/groups, personal fatwas or unnecessary identity data. It conservatively refers sensitive/disputed cases. The bounded planner selects the current graph, indexed library or live approved references. Compiler-teacher answers use actual recorded edges and state the library's limited coverage.

Stored evidence covers ten reports, 22 paths and 74 narrator identities. Live reference search uses the official Islamic Content MCP and fetches original records with their exact printed URLs. HadeethEnc records additionally require publisher grade and attribution. There is no unrestricted model web access or claim to search every book. Original passages are not treated as instructions.

The model writes a short answer with evidence IDs. The server verifies existing citations, literal quotations, narrator ownership, relationship direction and material appraisal qualifiers. A separate model request checks each paragraph against its own evidence. One correction attempt may use the same original evidence, then passes the same checks. Unsupported output is withheld or replaced by clearly labelled original source evidence; a fallback is never presented as generated AI. Automated checks do not replace human approval.

## Extraction

Known matns can open a reviewed library map. Other inputs use a specific approved source page or bounded source search. A retrieved matn without an explicit isnad cannot create a chain. Pasted full source text supports a literal parser and, with a valid provider, structured AI extraction. Exact name/link spans are validated. Missing intermediaries, unresolved pronouns and unconnected branches remain unresolved. Only the explicitly reviewed Bukhari 59 identity join may resolve the specific “أبي” mention, using Shamela original wording and Taqrib 6228. No general short-name merging is allowed.

Drafts are separate from the approved library. They assign no narrator grade and can be downloaded as source-span evidence for review. Source failure is disclosed rather than silently replaced by a guessed chain.

## Practice and map actions

Exercises and correct options are derived from recorded directed edges and joins. The model selects an exercise and explains it from those records. Scoring uses the server's graph-derived answer, not a client-supplied score. Map actions choose from existing graph selections only; no model-supplied code, arbitrary coordinates, new narrators or edges run in the browser.

## Sources and limitations

[Source audit](SOURCE-REVIEW.md) · [API directory](API-SOURCES.md) · [Privacy](PRIVACY.md) · [Guide compliance and pending review](SCIENTIFIC-REFERENCE-COMPLIANCE.md).

Source calls have fixed hosts, no credentials, no redirects, bounded responses and 12-second timeouts. Model calls remain server-side with bounded inputs and a 25-second per-call timeout. Providers may have independent quotas/outages. Authentication or quota failures do not trigger an automatic paid upgrade. Dorar live access was blocked during review; its adapter fails closed while previously verified library evidence remains readable. A valid model key is required for generated AI features; source mode and literal parsing are disclosed as non-AI.
